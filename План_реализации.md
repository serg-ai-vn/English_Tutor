# План реализации

## Архитектура: два независимых трека

**Track A - учёба.** Активный 7-урочный цикл: один главный навык за урок, learner-facing блок ведёт отдельный агент, основной чат оркестрирует и пишет состояние.

**Track B - сборка системы.** Сейчас локальные интерфейсы (Codex, OpenCode, Claude Code, Cursor и др.) используют общие промпты и JSON. Целевой вторичный путь Supabase -> n8n -> Telegram + Whisper остаётся отложенным до сервера.

Обычный урок планируется на 25–30 минут для всех дней и Refresher; 35 минут — абсолютный hard cap, новые вопросы прекращаются на 25-й минуте. Сборка Track B - отдельное время, не в ущерб учёбе.

Дедлайн-якорь: запуск курса через 1-2 месяца. Неделя 8 программы - полная готовность питча. Горизонт плана - 12 недель, дальше английский продолжается как долгосрочная цель.

## Стартовая последовательность (дни 1-4)

Исследование занимает 1-2 дня, не недели - поэтому Track A стартует с реальной программы, а не с долгой заглушки:

- День 1: диагностика + baseline (шаги 0.1-0.2) + запуск исследований шагов 1-2 (промпты готовы, Deep Research работает в фоне)
- День 2: рутина 0.4 как заглушка + разбор отчётов шагов 1-2, при необходимости один уточняющий запрос. В блоке "Вход" вместо подкаста можно читать свои материалы курса (см. `track_A/program/course_base_index.md`)
- День 3: синтез программы (шаг 3) + одобрение. Вечером - первый день по program.json
- День 4+: учёба идёт только по program.json

Страховка: если к вечеру дня 3 программа не одобрена - рутина 0.4 продолжается, исследование добивается одним запросом. Заглушка длится максимум 3 дня; учебный день не пропускается никогда.

### Шаг 4-L - Локальный мульти-агентный прототип

Контекст: сервер с n8n + Supabase пока недоступен. Главный путь — один протокол в `track_B/local/protocol.md`, который исполняется через Codex, OpenCode, Claude Code или любую другую агентную среду. Данные копятся в JSON со структурой будущей Supabase-схемы.

**Принципы:**
- Всё живёт в `track_B/local/` внутри папки проекта
- База данных = JSON-файлы. Старые таблицы сохраняют миграционные поля шага 4; `lesson_sessions` и `error_events` — локальное расширение, которое нужно добавить в DDL перед будущей миграцией
- Основной чат — оркестратор/единственный писатель; каждый учебный блок ведёт отдельный read-only агент с узким контекстом (или режим ролевой изоляции `Single-Agent Fallback`)
- API-ключи и скрипты-коннекторы НЕ нужны: транскрипты голоса ученик присылает текстом в чат; CAF-метрики = 3 прогона промпта `check_monologue_caf.md` в чате → медиана → флаг надёжности (разброс > 15% = `reliable: false`)
- Один опциональный скрипт - `track_B/local/median.js` без внешних зависимостей: вставить 3 JSON прогонов CAF, получить медиану и флаги - для единообразного формата записи
- Codex использует проектные роли `.codex/agents/*.toml`, OpenCode — `.opencode/agents/*.md`, прочие среды — субагентов или режим ролевой изоляции; все они напрямую читают канонические `track_B/prompts/` без промежуточных переадресаций и жёсткого хардкода модели

**Структура:**

| Путь | Назначение |
|---|---|
| `track_B/local/db/` | JSON-база: tasks/SRS/assessments/speaking; `lesson_sessions.json` хранит время и причины; `error_events.json` — occurrence-слой всех обнаруженных ошибок; `error_log.json` — агрегированные recurring/high-impact candidates |
| `track_B/local/protocol.md` | канонический протокол урока |
| `track_B/local/median.js` | опционально: 3 JSON CAF → медиана + флаги надёжности (без API) |
| `.opencode/agents/` | субагенты opencode (тонкие обёртки над `track_B/prompts/`): изолированный контекст на блок урока, read-only |
| `.codex/config.toml`, `.codex/agents/` | лимит до 3 Codex-агентов и проектные read-only роли |
| `track_A/LESSON_START.md` | короткая инструкция нового учебного чата без перечитывания всего проекта |
| `track_B/prompts/analytics_contract.md` | единый формат тихого сбора learner turns и ошибок |
| `track_A/transcripts/index.md` | индекс неизменённых исходных чатов и доказуемых полей времени |
| `track_A/today.md` | план текущего дня - единственный источник правды для всех блоков (перезаписывается ежедневно) |
| `track_A/progress.json` | текущая неделя/день, счётчик завершённых дней, накопительные `covered_grammar` и `introduced_material` |

**Протокол урока (исполняет основной чат):**

1. Новый учебный чат: команда «Начинаем урок» и лёгкий маршрут из `track_A/LESSON_START.md`; полный мастер-план не перечитывается.
2. `today.md`: только текущий день программы, один отсортированный пакет максимум из 5 SRS-повторов (`due_lesson ASC`, `lapses DESC`, `id ASC`), максимум 2 новых карточки и один главный навык. Первичный пакет — 5 минут learner-active time; model wait исключается; только ошибочные номера получают один общий retry до 2 минут. Всё фактическое SRS-время сверх 5 минут вычитается из главного блока.
3. Каждый learner-facing блок исполняет named agent; оркестратор передаёт literal `today.md`, `covered_grammar`, `introduced_material`, узкий payload и `analytics_contract.md`.
4. Закрытие сразу после блока: оркестратор раздельно пишет planned/productive/wall-clock time, session record, occurrence errors, speaking transcripts, tasks, SRS и progress. Лимит feedback не ограничивает тихое хранение.
5. Day 7: лёгкий review; W4/W8/W12 benchmark делится на day 6 (монолог/CAF) и day 7 (EF SET), чтобы не превысить timebox.

**Миграционный путь (когда появится сервер):**
- `track_B/local/db/*.json` → импорт в Supabase (скрипт `migrate_to_supabase.js`): каждый JSON-файл → соответствующая таблица, поля уже совпадают
- Протокол дня → n8n воркфлоу WF-1..WF-4: логика та же, ноды вместо чата
- Локальный чат → Telegram-бот: промпты и JSON-структура не меняются, меняется только канал доставки

Критерий готовности: единый `protocol.md`, рабочие роли Codex/OpenCode, один писатель состояния, валидная JSON-база; стартовая команда явно ведёт в `track_A/LESSON_START.md`; каждый закрытый урок имеет session/time/error telemetry; benchmark CAF выдаёт 7 полей, медиану и флаг надёжности.

# TRACK A

## Шаг 0 - Диагностика и ручная рутина (день 1)

Цель: объективно зафиксировать уровень и запустить ежедневный цикл без инструментов.

Режим исполнения (с 2026-08-26): урок выполняется по единому протоколу. Учебные блоки ведут субагенты; основной чат планирует и обновляет состояние. EF SET и запись монолога на телефон делает владелец.

### 0.1 Диагностика уровня (день 1, один раз)

День 1 - только диагностика (0.1) и базовая запись (0.2), без рутины. Ежедневная рутина 0.4 стартует со дня 2 - иначе день 1 выходит за окно 45-60 минут.

Пройти два бесплатных теста, результаты записать в `track_A/logs/diagnostics.md`:

1. EF SET - `https://www.efset.org/` (короткий 15-минутный вариант; полный 50-минутный - только если день 1 позволяет, он точнее по CEFR)
2. Cambridge - `https://www.cambridgeenglish.org/test-your-english/` (быстрый ориентир)

### 0.2 Базовая запись говорения (10 минут, один раз)

Записать на телефон монолог 2 минуты на тему:

> I'm launching an AI course for Vietnamese children. I'll explain why my methodology works, what problems parents have, and how my platform solves them.

Дальше: прогнать запись через Whisper (или любой бесплатный transcriber), текст + свои ощущения сохранить в `track_A/speaking/baseline.md`. Это точка отсчёта - через 4 и 8 недель повторяем тот же монолог и сравниваем.

### 0.3 Базовый набор материалов (бесплатно)

| Навык | Материал | Как использовать |
|---|---|---|
| Грамматика | Темы по `program.json`; книга не требуется | Один узкий target/контраст, контролируемая практика и одна повторная попытка |
| Аудирование | Аудио с транскриптом/субтитрами | Day 5: 18-22 мин, до 3-5 предслов перед незнакомым акцентом, затем comprehension и shadowing |
| Говорение | Голосовой режим LLM или запись на телефон | Speaking/data/pitch по циклу, отложенно максимум 2-3 коррекции |
| Чтение | Тексты про курс, работу, клиентов и общую жизнь | 10-14 предложений, до 3 предслов, максимум 2 chunks |

### 0.4 Активный 7-урочный цикл

| День | Навык | Плановое время |
|---|---|---:|
| 1 | grammar | 40-50 мин |
| 2 | speaking | 40-45 мин |
| 3 | reading | 40-45 мин |
| 4 | data speaking | 40 мин |
| 5 | 2 patterns + listening + drilling | 45-50 мин |
| 6 | pitch / mock pitch | 45-50 мин |
| 7 | light review или benchmark | 30-45 мин |

SRS в дни 1-6: один пакет максимум из 5 повторов, самые старые `due_lesson` первыми; один ответ ученика и одна общая проверка. Первичный retrieval — 5 минут learner-active time без model wait; при ошибках разрешён один общий retry до 2 минут. Всё learner-active SRS-время сверх 5 минут сокращает главный блок. Новых элементов максимум 2; после подтверждения они сохраняются с `reps: 1` и `due_lesson: lesson_number + 1`, тогда как `reps: 0` означает ещё не введённый seed. Не каждая ошибка становится карточкой.

Day 7 - лёгкий review без календаря. Полный benchmark проводится только W4/W8/W12: монолог/CAF на day 6, EF SET на day 7.

### Канонические промпты Track A

Полные тексты промптов не дублируются в мастер-плане. Единственный источник правды — `track_B/prompts/`; project-agent files являются тонкими read-only обёртками.

| Задача | Канонический промпт |
|---|---|
| SRS | `srs_review.md` |
| grammar lesson / check | `grammar_lesson.md`, `check_grammar.md` |
| speaking / data speaking | `tutor_speaking.md`, `data_speaking.md` |
| reading | `reading_tutor.md` |
| patterns + listening | `patterns_listening.md` |
| pitch / mock pitch | `pitch_coach.md`, `mock_pitch.md` |
| monologue practice / benchmark | `check_monologue.md` |
| benchmark CAF | `check_monologue_caf.md` — только W4/W8/W12, три параллельных прогона |
| weekly review | `weekly_review.md` |

Оценка всегда получает `covered_grammar`; speaking/data/pitch также получают `introduced_material`. Practice feedback ограничен, полный рубрикатор используется только в benchmark mode.

### Артефакты шага 0

- `track_A/logs/diagnostics.md` - результаты тестов
- `track_A/speaking/baseline.md` - транскрипт базового монолога
- `track_A/logs/YYYY-MM-DD.md` - ежедневные логи (шаблон: Сделано / Новые chunks / Ошибки)

# TRACK B

## Шаг 1 - Исследование методологий

Цель: evidence-based методика B2 -> C1 под профиль 45-60 мин в день.

Где выполнять: Gemini Deep Research (бесплатный тир). Артефакт сохраняется в `track_B/research/research_methodology.md`.

## Шаг 2 - Исследование материалов и доменного языка

Цель: каталог материалов + языковой арсенал для продажи курса.

Где выполнять: Gemini Deep Research + NotebookLM. Артефакт сохраняется в `track_B/research/research_materials.md`.

## Шаг 3 - Синтез программы

Цель: из двух исследований + базы собственного курса получить персональную 12-недельную программу в машиночитаемом JSON (`track_A/program/program.json`). Третий обязательный вход — база собственного курса (`track_A/program/course_base_index.md`).

*(Исходные одноразовые промпты генерации для выполненных шагов 1–3 удалены после завершения синтеза программы).*

## Шаг 4 - Схема Supabase

Цель: база для программы, прогресса, SRS и ошибок. Артефакт - `track_B/schema/schema.sql` (создать при сборке; ниже референс).

Fit-check перед созданием таблиц (10 минут, обязательно): взять `program.json` шага 3 и проверить, что каждый день программы раскладывается в поля `daily_tasks` (skill / duration_min / activity / material_ref), а milestone недели - в `program_weeks.milestone`. Также включить локальные расширения `lesson_sessions` и `error_events`.

Референс DDL:

```sql
create table program_weeks (
  id bigint generated always as identity primary key,
  week_no int not null,
  goal text,
  milestone jsonb,
  starts_on date,
  ends_on date
);

create table daily_tasks (
  id bigint generated always as identity primary key,
  task_date date not null,
  week_id bigint references program_weeks(id),
  skill text not null,          -- grammar|speaking|listening|reading|srs|pitch
  duration_min int not null,
  activity text not null,
  material_ref text,
  status text not null default 'pending'
    check (status in ('pending','done','skipped')),
  notes text
);

create table materials (
  id bigint generated always as identity primary key,
  title text not null,
  type text,                    -- book|podcast|video|course|article
  url text,
  domain text,                  -- pitch|general
  level text,
  how_to_use text
);

create table srs_items (
  id bigint generated always as identity primary key,
  item_type text not null check (item_type in ('chunk','vocab','grammar','pattern')),
  front text not null,
  back text not null,
  topic text,
  due_lesson int not null default 1,
  interval_lessons int not null default 1,
  ease numeric not null default 2.5,
  reps int not null default 0,
  lapses int not null default 0
);

create table study_sessions (
  id bigint generated always as identity primary key,
  session_date date not null default current_date,
  planned_min int,
  actual_min int,
  tasks_done int,
  mood int
);

create table error_log (
  id bigint generated always as identity primary key,
  created_at date not null default current_date,
  skill text check (skill in ('speaking','writing')),
  error_text text,
  correction text,
  grammar_topic text,
  times_seen int not null default 1,
  resolved boolean default false
);

create table speaking_recordings (
  id bigint generated always as identity primary key,
  recorded_at date not null default current_date,
  transcript text,
  ai_feedback jsonb,
  error_count int,
  duration_sec int
);

create table assessments (
  id bigint generated always as identity primary key,
  assessed_at date not null default current_date,
  type text,                    -- weekly_monologue|mock_pitch|test
  scores jsonb,
  notes text
);
```

## Шаг 5 - n8n: ежедневные задания и чекин

Цель: бот сам присылает план на день и принимает отчёт. Артефакты - `track_B/workflows/` (описания + экспорт JSON).

## Шаг 6 - Telegram + Whisper: фидбек по говорению

Цель: голосовое сообщение -> транскрипт -> разбор ошибок + 3 параллельных прогона `check_monologue_caf.md` с расчётом медианы.

## Шаг 7 - Еженедельный обзор

Цель: автоотчёт после каждого седьмого завершённого урока и одна ограниченная корректировка следующего цикла (`track_B/prompts/weekly_review.md`).

## Шаг 8 - Миграция ручных данных

Цель: JSON-таблицы из `track_B/local/db/*.json` переезжают в Supabase, ничего не теряется.

# Контракт качества

Целевые метрики (проверять по данным системы):

| Метрика | База (шаг 0) | Цель к неделе 8 |
|---|---|---|
| Streak | 0 | >= 6 дней в неделю |
| Ошибки в монологе питча | baseline | -50% к неделе 8 |
| Mock pitch (промпт T-A4), grammar | не измерялось | >= 8/10 |
| Грамматика (темы по плану Hewings, мини-уроки в чате) | 0 тем | база закрыта, продвинутые темы в работе |
| SRS-карточки | 0 | >= 300 chunks, просрочка < 10% |

## Правило MVP для Track B

Каждый шаг Track B самодостаточен: если сборка серверной части отложена, локальный прототип полностью обеспечивает учебный процесс. Никогда не останавливать учёбу ради доработки инструмента.


## P25 — утверждённый стандарт 2026-10-27

Все уроки: 25–30 минут (5 SRS + 20–25 главный навык), абсолютный hard cap 35 минут, stop-new-questions на 25-й минуте, видимая строка `⏱ [Блок X/2 | Шаг Y из Z | ~M/30 мин]`, независимый лимит шагов и таймер при доступных часах. В уроке speaking до 3 ходов; grammar 3 controlled + 2 guided предложения; reading 8–10 предложений и 2 вопроса; Refresher 4 grammar + 2 speaking. Аналитика не создаёт дополнительные задания. Время ожидания модели учитывается отдельно и не подменяется догадкой.


## Текущее исполнение P26

DDL/серверный Track B — справочный проект, не обязательная инфраструктура урока. Действующие квоты, старт и публикация определены lesson_contract.md.


Текущее исполнение и сохранение: `track_B/local/lesson_contract.md`. Перед уроком прочитать его; подтверждение успеха только после перечитывания main. Копия старого проекта владельца — архив.
