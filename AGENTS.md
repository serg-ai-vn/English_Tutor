# English_Tutor — правила проекта

## Единая точка входа (для любого ИИ-агента и среды)

Чтобы ни один агент не придумывал собственные правила при смене приложения, IDE или модели (OpenCode, OpenAI Codex, Claude Code, Cursor, Windsurf или облачный агент на GitHub), проект опирается на строгую иерархию из 4 уровней:

1. **`AGENTS.md` (этот файл)** — конституция проекта и глобальные ограничения. Автоматически считывается при старте в **OpenCode**, **OpenAI Codex** и **Cursor** (а в **Claude Code** — через указатель `CLAUDE.md`).
2. **`track_A/LESSON_START.md`** — точка входа для проведения урока (по команде **«Начинаем урок»** или **«Давай повторим пройденное после перерыва»**).
3. **`track_B/local/protocol.md`** — канонический протокол 7-урочного цикла, режима повторения после перерыва, формата `track_A/today.md`, закрытия дня и синхронизации с GitHub.
4. **`track_B/prompts/*.md` + `analytics_contract.md`** — **единственный источник правды** по поведению каждого из 12 учебных блоков.

> **Экономия контекста:** база курса (`course_base/`, 24 файла) и исторический архив сессий (`track_A/logs/session_history_1_34.md`) не читаются целиком при запуске урока. Читай только `track_A/program/course_base_index.md` или ровно один файл из `course_base/`, если он указан в плане сегодняшнего урока.

## Цель проекта

Два горизонта результата:

1. **Ближайший дедлайн (12-недельный интенсив):** уверенный B2+/приближающийся к C1 профессиональный английский для 8–10-минутного питча AI-курса, демонстрации и Q&A с образовательными центрами.
2. **Долгосрочная цель:** полноценный разговорный C1 для повседневной жизни, преподавания, AI-интеграции, клиентов и бизнес-партнёров. Этот трек не заканчивается после запуска курса и не считается гарантированно закрытым за 12 недель.

## Профиль ученика

- Преподаватель английского во Вьетнаме, параллельно AI-интегратор (n8n + Supabase + API)
- Говорение/понимание: ~B2, грамматика хромает — нужен полный разбор
- Приоритет: говорение без грамматических ошибок на темы продажи курса (методология обучения, боли родителей и учеников, исследование рынка, устройство платформы)
- Бюджет: в основном бесплатные ресурсы, небольшой бюджет только если реально стоит того
- Время: 25–30 минут в день (P25; hard cap 35 минут)

## Жёсткие правила

1. **Вся инфраструктура живёт только внутри папки `English_Tutor` (корня репозитория).** Агент не выходит за её пределы даже в режиме чтения. Если выход необходим, агент сначала запрашивает разрешение у владельца и указывает: зачем это нужно, что конкретно он хочет сделать, какие файлы затронет. Без явного «да» — никаких действий снаружи. Копирование внешних материалов в папку выполняет сам владелец.
2. **Два независимых трека.** Track A (учёба) работает непрерывно по локальному протоколу. Track B (сборка серверной системы) идёт параллельно и никогда не блокирует учёбу.
3. **Учёт времени:** обычный урок планируется на 25–30 минут, день 7 — на 25–30 минут; **hard cap 35 минут**. Дополнительные упражнения не добавляются поверх плана. До отметки урока как `completed` оркестратор фиксирует фактическое время ученика (`actual_learning_min`) в целых минутах; оценка «на глаз» или «не зафиксировано» не заменяют это поле.
4. **Метаданные файлов:** каждый новый `.md`-файл — с YAML frontmatter (`title`, `created`, `updated`, `tags`, `status`, `related`). Исключения: служебные файлы (`README.md`, `CLAUDE.md`, `.gitignore`), обёртки `.opencode/agents/*.md`, конфиги `.codex/config.toml` и `.codex/agents/*.toml`, JSON-файлы данных (`track_B/local/db/*.json`, `track_A/progress.json`).
5. **Защита от удаления и перезаписи:** файлы не удалять и не перезаписывать без явного разрешения. Исключения — рабочие файлы дня: `track_A/today.md` (план дня, перезаписывается каждый учебный день) и `track_A/progress.json` (текущая неделя/день, обновляется при закрытии урока), а также append/update записей в `track_B/local/db/*.json`, `Корректировки_урока.md` и `session.md` по протоколу закрытия урока.
6. **GitHub-дисциплина:** живой main — источник состояния. Перед уроком и после сохранения проверить удалённую версию. Один комплект/commit, без перезаписи чужих изменений; после отправки перечитать все файлы. Обязательный контракт: `track_B/local/lesson_contract.md`. Старая локальная копия владельца — архивный черновик.

## Правила урока (антишум)

Действуют всегда, для оркестратора и всех субагентов:

1. **Язык по умолчанию — английский:** объяснения и задания по умолчанию на английском. На русский переключаться ТОЛЬКО по прямому запросу ученика («объясни по-русски»). Если ученик не понял по-английски — не переключаться, а переформулировать на английском проще и подробнее: разбить на шаги, дать пример выполнения.
2. **Тихий бэкенд:** не проговаривать служебные действия (запись в файлы, логирование, аналитику, git-команды) — делать молча при успехе. Сбой, частичное сохранение и конфликт немедленно сообщать по track_B/local/lesson_contract.md; verified_main подтверждать квитанцией.
3. **Маркеры блоков:** любой блок контента помечать типом в начале строки: `[КАРТОЧКА]` / `[НОВЫЙ ПАТТЕРН]` / `[КОРРЕКЦИЯ]` / `[ЗАДАНИЕ]` / `[ТЬЮТОР В РОЛИ]`. Один блок — один тип. Внутри ввода новых карточек разные типы = разные подзадания с маркерами `[НОВОЕ СЛОВО]` / `[НОВЫЙ CHUNK]` / `[НОВЫЙ ПАТТЕРН]` — никогда не смешивать их в одну выдачу.
4. **Ввод C1-паттернов только в Day 5:** новый C1-паттерн вводится только в запланированном блоке day 5: сначала естественный пример на английском, затем короткое объяснение и контролируемая попытка. В speaking/data/pitch новый паттерн не вводится и не требуется. Фраза «Мы это не учили» = стоп-сигнал: немедленно снять требование без замены новым материалом и продолжить с уже пройденным.
5. **Роль скептичного директора:** включается только в `mock_pitch` (недели 6–12) с явным объявлением `[ТЬЮТОР В РОЛИ]`. Внутри обычной разговорной практики не включать.
6. **Компактность:** план дня — одним блоком в начале; переходы между блоками — одной строкой; никаких лирических отступлений и непрошеных дополнительных материалов.
7. **Однозначность заданий:** каждое задание содержит развёрнутую инструкцию на английском — что именно показано, что ученик должен сделать, что прислать/сказать в ответ и в каком виде. Перед выдачей проверка: «можно ли понять это задание двумя способами?» — если да, переформулировать подробнее.
8. **Все учебные материалы — только в чате:** правила, тексты для чтения, упражнения и примеры выдаются прямо в сообщении, целиком. Никаких отсылок «открой книгу/файл» как способа выдачи материала; книга Hewings не используется (номера юнитов в программе — только метки тем).
9. **Speaking / Data / Pitch = только применение уже введённого материала:** требовать можно лишь грамматику, паттерны и карточки из списка `introduced_material` в `today.md`. Новый материал в этих блоках не выдаётся.
10. **Reading — преимущественно новые факты:** повтор известного <= 30% и помечается `(review)`; до текста даются максимум 3 необходимых слова; текст обычно 8–10 предложений; из него выбираются максимум 2 полезных chunks для SRS.
11. **Оценка — только по пройденному:** `check_grammar`, `tutor_speaking`, `check_monologue` и `mock_pitch` считают ошибками только структуры из `covered_grammar`; непройденная структура = `(not yet covered - info)` без штрафа, разбора, дополнительного упражнения, агрегированного `error_log` и SRS. Для тихой аналитики сам случай всё равно сохраняется в `error_events.json` с `covered_status: not_yet_covered`.
12. **Календарь не используется:** только порядковые номера уроков (`progress.json`). SRS-повторы идут по `due_lesson`; выбрать максимум 5 карточек (`status != deprecated`, `reps > 0`, `due_lesson <= lesson_number`) и отсортировать строго по ключу `(due_lesson ASC, lapses DESC, id ASC)`. Самая старая просрочка всегда идёт первой, порядок исходного JSON игнорируется. Остаток очереди переносится без изменения, объём урока не раздувается за пропущенные дни.
13. **Пакетный SRS-timebox:** все максимум 5 `front` выдаются одним нумерованным сообщением, ученик отвечает на 1–5 одним сообщением, затем получает одну общую проверку. Первичный retrieval имеет цель 5 минут learner-active time; ожидание модели/агента не считается. Только ошибочные номера могут получить один общий retry максимум на 2 дополнительные learner-active минуты. Всё фактическое learner-active SRS-время сверх 5 минут заменяет такой же объём главного блока и не удлиняет урок. Никаких последовательных выдач по одной карточке и дополнительных SRS-раундов.
14. **Два режима коррекции:** в accuracy/drill исправляется только целевая структура и требуется одна повторная попытка; во fluency/speaking агент не перебивает и после попытки даёт максимум 2–3 высокополезные коррекции. Полный learner-facing разбор — только на контрольных срезах W4/W8/W12. Это ограничение относится к показу ученику, а не к хранению: все обнаружимые случаи из содержательных английских ответов молча возвращаются оркестратору по `track_B/prompts/analytics_contract.md`.
15. **Общий C1, а не только питч:** ориентир тем курса — 50% AI-курс/продажи, 30% преподавание/AI-работа/клиенты, 20% повседневная и социальная речь. Каждая новая грамматика или паттерн переносится как минимум в профессиональный и общий контекст внутри основного блока.
16. **Лимит новых SRS:** максимум 2 новых элемента за урок ввода. Фактически введённая и подтверждённая учеником карточка сразу сохраняется как `status: active`, `reps: 1`, `interval_lessons: 1`, `due_lesson: lesson_number + 1`; иначе фильтр повторов `reps > 0` её не увидит. Карточка ошибки создаётся только для повторяющейся или мешающей пониманию ошибки и заменяет один из двух слотов, а не добавляется сверху. Опечатки и одноразовые slips остаются только в `error_events.json`.
17. **Замечания ученика прямо во время урока:** если ученик прямо посреди урока говорит, что ему не нравится подача, правило или поведение агента, оркестратор **немедленно** фиксирует это замечание в разделе `Pending` файла `Корректировки_урока.md` и учитывает пожелание на текущем шаге, а системная правка промптов выполняется после урока или в отдельном чате (Сценарий Б).

## Оркестрация урока (Мульти-агентный и универсальный режимы)

Урок = один чат. Основной агент — оркестратор и **единственный писатель** в базу и логи.

### Как вызываются учебные блоки в разных средах:
Все среды используют **одни и те же канонические промпты из `track_B/prompts/`**:
- **OpenAI Codex:** вызывает проектных субагентов `.codex/agents/<role>.toml`.
- **OpenCode:** вызывает субагентов `.opencode/agents/<role-kebab>.md` (`@srs-review`, `@grammar-lesson`, `@check-grammar`, `@tutor-speaking` и т.д.).
- **Claude Code / Cursor / другие агентные IDE с инструментом субагентов (`Task`):** запускает read-only субагента с инструкцией прочитать `track_B/prompts/<prompt_file>.md` и `track_B/prompts/analytics_contract.md`, передавая ему буквальный `track_A/today.md` и узкий payload блока.
- **Single-Agent Fallback (если среда не поддерживает субагентов или работает в облачном веб-чате):** основной агент исполняет блок в режиме **строгой ролевой изоляции** — перед началом блока читает только соответствующий промпт из `track_B/prompts/<prompt_file>.md`, действует строго в рамках списков `SRS reviews`, `introduced_material` и `covered_grammar` из `track_A/today.md` и не читает другие файлы базы до завершения блока.

### Порядок проведения урока:
1. **Старт (команда «Начинаем урок» или «Давай повторим пройденное после перерыва»):** следовать `track_A/LESSON_START.md`; проверить живой main и рабочее состояние по `track_B/local/lesson_contract.md`; текущий урок `N = days_completed + 1` (либо режим `Refresher` без сдвига счётчика уроков, если ученик попросил освежить память после долгого перерыва).
2. **Контракт дня (`track_A/today.md`):** оркестратор записывает план в `track_A/today.md` — единственный источник правды на день. Ни один блок и ни один субагент не использует карточки, паттерны или материалы, не перечисленные в этом файле. План выдаётся одним компактным блоком, затем ожидается подтверждение ученика.
3. **1 навык в день:** SRS-разминка + один главный навык:
   - Day 1: `srs_review` -> `grammar_lesson` -> `check_grammar` (`check_grammar.md`)
   - Day 2: `srs_review` -> `tutor_speaking` (`tutor_speaking.md`)
   - Day 3: `srs_review` -> `reading_tutor`
   - Day 4: `srs_review` -> `data_speaking`
   - Day 5: `srs_review` -> `patterns_listening`
   - Day 6: `srs_review` -> `pitch_coach` (W1–W5) или `mock_pitch` (W6–W12)
   - Day 7: запланированный лёгкий input/benchmark -> `weekly_review` (на W4/W8/W12 day 6 включает benchmark-монолог `check_monologue` + три параллельных прогона `check_monologue_caf`).
4. **Read-Only дисциплина блоков:** субагенты ничего не пишут в файлы. Все результаты и `ANALYTICS_PACKET` возвращаются оркестратору.
5. **Listening на незнакомом акценте:** первый проход с субтитрами/транскриптом; 3–5 незнакомых слов вводятся ДО прослушивания, не после.
6. **Закрытие:** получить actual_learning_min, собрать и проверить комплект по `track_B/local/lesson_contract.md`. Учебное завершение отдельно от verified_main. При сбое сообщить сразу; успех только после перечитывания удалённого комплекта.

## Протокол сессии

### Сценарий А: Новый чат учебного урока (или повторения после перерыва)

1. Проверить живой main и рабочее состояние по `track_B/local/lesson_contract.md`.
2. Прочитать `AGENTS.md` и `track_A/LESSON_START.md`.
3. Прочитать только перечисленные в `LESSON_START.md` минимальные файлы (`progress.json`, текущий день `program.json`, очередь `srs_items.json`, `analytics_contract.md`, раздел `Pending` в `Корректировки_урока.md`).
4. **Не читать** полный `session.md`, `План_реализации.md`, `track_B/research/*`, `course_base/*` (если текущий урок не требует конкретного текста) и `track_A/logs/session_history_1_34.md`.
5. Создать/обновить `track_A/today.md`, показать компактный план и ждать подтверждения ученика.
